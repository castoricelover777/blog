# 杨子颉的个人全科知识库

一个用 **HTML5 + 原生 CSS + 原生 JavaScript** 写的个人知识库，用来沉淀大一至今所有学科的学习记录
（C语言、数据结构、Java、算法……）。只有 **marked.js** 一个外部库（把 Markdown 渲染成 HTML），
没有框架、没有数据库、没有后端。

- **代码量**：`js/app.js` **776 行**（其中代码 374 行、注释 285 行、空行 117 行）；
  `index.html` 324 行（含全部样式）；样式写在 `index.html` 的 `<style>` 里，没有单独的 css 文件；
- **语法**：只用 `let`、`function`、`for` 循环、`if-else`，以及 `push / splice / indexOf / slice` 这些基础方法。
  **没有**箭头函数、模板字符串、解构赋值、`const`、`map/filter/forEach`；
- **交互**：新增用连续 `prompt()` 问答，编辑用 `prompt()`，删除用 `confirm()`，没有弹窗组件和表单；
- **数据**：`data/notes.json` 文件 + 浏览器 `localStorage` 双保险。

## 二、怎么打开

**✅ 双击 `启动知识库.bat`** —— 它会启动一个只监听本机的小服务器，并自动打开浏览器
（地址形如 `http://127.0.0.1:8080/`）。关掉那个黑色窗口就是停止服务器。

**为什么不能直接双击 `index.html`？**
那样地址栏是 `file://…`，浏览器出于安全策略不允许 JavaScript 读取本地文件，
所以第一次打开会读不到 `data/notes.json`（页面会给你一句提示）。
用 bat 打开就没这个问题。这个限制和代码无关，是浏览器的**同源策略**。

> 端口被占用时服务器会自动往后找（8080 → 8081 → 8082……最多试 40 个），
> 以窗口里打印的 URL 为准。

## 四、⚠️ 数据到底存在哪里（这段最重要）

数据同时存在于两个地方，规则很简单：

```text
打开页面时：
    1. 先把 localStorage 里的数据立刻显示出来（所以页面不会白屏）
    2. 同时去问服务器：磁盘文件里的最新数据是哪一版？
         文件里有更新的 ──> 自动换成文件里的，并弹一句提示
         两边一样或缓存更新 ──> 什么都不做，继续用缓存
         服务器连不上 ──> 继续用缓存（离线也能看）

每次增/删/改：
    localStorage 立刻更新（磁盘文件不动，除非你点【💾 保存到文件】）
```

> **为什么改成这样（2026-10-10 的改动）**：
> 以前是"只要 localStorage 里有数据就永远用缓存"，结果出现了很折腾的情况——
> 在电脑上导入了 40 条笔记，浏览器里却还显示几十天前的 5 条，**非得手动按 F12 清缓存才能看到最新内容**。
> 现在改成：**缓存只负责"先显示出来"，磁盘文件才是"最终依据"。**
>
> 怎么判断哪边更新：比较两边**最新那条笔记的 `created` 时间**（精确到分钟）。

由此带来几条**你一定要知道**的结论：

1. **点开 `启动知识库.bat` 就能看到文件里的最新数据**——不用再清缓存了。
   这条现在会自动完成，你会看到一句"已自动同步"的提示。
2. **刷新、关掉再打开，改动都不会丢**——因为缓存在浏览器里。
3. **想让磁盘文件也更新**，点【💾 保存到文件】（本地）或【⬇ 下载数据】再手动覆盖。
   磁盘文件更新了，才谈得上 `git commit` 和 `git push`。
4. **⚠️ 反过来要注意**：如果你在网页上改过东西、**没点【💾 保存到文件】**，
   而磁盘文件又比缓存新（比如我在电脑上导入了新笔记），
   **打开页面时缓存里的改动会被文件覆盖掉。**
   ——所以网页上改完就顺手点一下保存，别攒着。
5. **万一需要强制以文件为准**，点顶部按钮 **【🔄 重新加载】**（或按 F12 执行
   `localStorage.removeItem('notes')` 后刷新）。两者的区别：
   - **自动同步**比较的是"最新那条的时间"，所以**只改了老笔记**这种情况它发现不了；
   - **【🔄 重新加载】**是无条件覆盖，任何改动都能同步过来。
6. 用 `http://127.0.0.1:8080` 打开和用 `file://` 双击打开，浏览器把它们当成**两个不同的地址**，
   各自的 `localStorage` 是**分开的**。所以固定用 `启动知识库.bat` 打开，别混着来。

### 一个必须理解的差别

| | `localStorage`（浏览器缓存） | `data/notes.json`（磁盘文件） |
| --- | --- | --- |
| 谁在用 | 只有你这台电脑的这个浏览器 | 网页首次打开时的初始数据；也是线上版本的数据 |
| 导师在线上看到的是 | —— 无关 | **你 push 上去的那一版** |
| 会不会自动同步 | **不会**，两个地方互相不知道对方改了 | |

所以：**在 GitHub Pages 上点【新增】只会存进访问者自己浏览器的缓存，不会影响你的数据。**
线上版本本质上是"只读展厅"，它展示的是你 `git push` 进去的那个 `notes.json`。

## 五、保存的两种方式，怎么选

### 方式一：【💾 保存到文件】（本地开发时用，推荐）

点一下，数据直接写进 `data/notes.json`。背后是 `tools/server.ps1` 提供的一个接口
`POST /api/save`，它会：

1. 先检查请求是不是合法 JSON、最外层是不是数组；
2. 把当前文件备份成 `data/notes.json.bak`（**上一版永远留着**，改错了能翻回来）；
3. 先写到临时文件，再改名覆盖正式文件——这样万一写到一半断电，正式文件还是完整的旧版本
   （这叫"原子替换"，写法在 `server.ps1` 的 `Save-Notes` 函数里）。

### 方式二：【⬇ 下载数据】（线上、或没有服务器时用）

浏览器会下载一个 `notes.json`，你把它复制到 `data/` 目录覆盖原文件。

> 在 GitHub Pages 上（没有后端），点【💾 保存到文件】会连不上，
> 代码会自动**退回**到"下载数据"这条路，不会让你白点。

## 六、Git 工作流（每天写完笔记就这几步）

### 最省事的办法：双击 `发布.bat`

它会自动做四件事，中间停下来问你两次：

1. 检查这个文件夹是不是 Git 仓库、`origin` 网址配好没有（有问题会直接告诉你怎么办）；
2. 列出你改了什么，然后问你一句 `Publish these changes? (y/n)` —— 输入 `y` 回车才继续；
3. 让你输入一句提交信息（比如 `add: 2026-10-10 数据结构 栈与队列`），回车即提交；
4. `git push` 推到 GitHub，最后打印线上网址。

> 这个脚本是**纯 ASCII**的（里面没有中文），这是故意的：`cmd.exe` 读 `.bat` 用的是系统
> OEM 代码页，中文会乱码甚至被当成命令执行。你在提示符后面**输入中文提交信息是没问题的**，
> 因为那段文字是传给 `git` 的参数，不经过 `cmd` 解析。

### 想自己敲命令的话

```bash
# 1. 看看自己改了什么
git status

# 2. 把改动加进来（. 表示"当前目录下所有改动"）
git add .

# 3. 提交，写一句人话说明这次干了什么
git commit -m "add: 2026-07-14 数据结构 栈与队列"

# 4. 推到 GitHub（第一次推要 -u，之后就一句 git push）
git push
```

### 一个完整的使用闭环（建议记住这个顺序）

```text
双击 启动知识库.bat   ->  在网页里写/改笔记  ->  点【💾 保存到文件】
                      ->  双击 发布.bat      ->  线上就是最新版
```

**注意第 3 步不能忘**：网页里的改动只存在浏览器的 `localStorage` 里，
不点【💾 保存到文件】就不会写进 `data/notes.json`，那 `发布.bat` 自然也就推不上去。
这是本项目唯一需要你记住的"两步走"。

**提交信息的写法建议**（不是硬规定，但养成习惯会显得专业）：

| 前缀 | 什么时候用 |
| --- | --- |
| `add:` | 新增笔记、新增功能 |
| `fix:` | 修 bug、改错别字 |
| `style:` | 只调样式、格式，不改逻辑 |
| `docs:` | 只改 README 这类文档 |

### 部署到 GitHub Pages（只需要做一次）

本项目的最终上线地址是：

```text
https://castoricelover777.github.io/blog/
```

1. 在 GitHub 上新建一个仓库，名字用英文 `blog`，选 **Public**
   （GitHub 的仓库名不支持中文，只允许字母、数字、`-`、`_`、`.`）；
   **不要**勾选 "Add a README file" 等初始化选项，让仓库保持空的，否则 push 会冲突；
2. 本地执行：

   ```bash
   git remote add origin https://github.com/castoricelover777/blog.git
   git push -u origin main
   ```

3. 打开仓库页面 → **Settings** → 左边找到 **Pages** →
   Source 选 **Deploy from a branch**，Branch 选 **main**、目录选 **/(root)**，点 Save；
4. 等一两分钟，访问上面的网址。

> **为什么这个项目用 "Deploy from a branch"，而不是 GitHub Actions？**
> 你另一个仓库 `ai-class-review` 用的是 Actions（`.github/workflows/pages.yml`），
> 那套东西适合有构建步骤的项目。本项目是纯静态的、根目录就是 `index.html`，
> 没有任何需要"编译"的东西，所以 Git 分支直接发布就够了——**少一个 yml 文件，少一处可能出错的地方**。
> 两种方式的效果完全一样。
>
> 想确认线上是不是真的活着，直接在浏览器打开那个网址；
> 或者命令行执行 `curl -I https://castoricelover777.github.io/blog/` 看有没有返回 200。

### ⚠️ 如果 `git push` 卡住或报 "Could not connect to server"

**这是本机网络环境的问题，不是代码的问题。** 现象是这样：

```text
fatal: unable to access 'https://github.com/...': Failed to connect to github.com:443
after 21077 ms: Could not connect to server
```

**原因**：这台电脑访问 GitHub 需要走代理（`127.0.0.1:7890`，由 `YueTuCore` 这个程序提供）。
浏览器能打开 GitHub，是因为浏览器会自动读 Windows 的"系统代理"设置；
但 **git 不会自动读**，它只会直连，于是被墙掉。

**解决办法**：给 git 单独配一次代理（配一次就永久生效）：

```bash
git config --global http.proxy http://127.0.0.1:7890
git config --global https.proxy http://127.0.0.1:7890
```

- 确认配好了：执行 `git config --global --get http.proxy`，
  如果打印出 `http://127.0.0.1:7890` 就说明生效了；打印空白说明没配上；
- **前提是代理软件正在运行**（任务栏里能看到它）。如果哪天你把代理软件关了，
  git push 就会又连不上——这时候要么打开代理软件，要么用下面这条把代理设置临时取消：

  ```bash
  git config --global --unset http.proxy
  git config --global --unset https.proxy
  ```

- 怎么判断代理端口是不是 7890：打开"Windows 设置 → 网络和 Internet → 代理"，
  看"手动设置代理"里的地址和端口；或者执行
  `Get-NetTCPConnection -LocalPort 7890 -State Listen` 看有没有程序在监听。

**注意**：GitHub Pages 是 **Linux** 服务器，而 Windows 不区分大小写。
所以文件名和路径要严格一致（`app.js` 不能写成 `App.js`，`data/notes.json` 的目录名也别改）。
本项目已经按这个原则写好，正常不会出问题。

**还要注意**：`.bat` 和 `.ps1` 是本地开发用的，推到 GitHub 上也不会执行，
它们只是当普通文件放着，不影响页面。想用它们得把整个项目 clone 到本地。

## 七、`data/notes.json` 的格式

就是一个数组，每条记录 5 个字段：

```json
[
  {
    "id": 1783612800000,
    "date": "2026-07-10",
    "title": "Java 基础：变量、数据类型与自动拆装箱",
    "category": "Java 基础",
    "content": "# Java 基础……\n\n正文用 Markdown 写\n"
  }
]
```

| 字段 | 说明 |
| --- | --- |
| `id` | `Date.now()` 生成的时间戳，唯一编号。**用来定位记录，不要手改，也不要有两条一样** |
| `date` | **必须是 `2026-07-10` 这种格式**，排序和归档分组都靠它（见下面的警告） |
| `title` | 标题 |
| `category` | 分类，网页顶部的分类药丸是自动从这里收集的 |
| `content` | Markdown 正文。JSON 里换行写成 `\n` |

> ⚠️ **`date` 的格式不能随便写。** 代码里用 `date.slice(0, 7)` 取年月来做归档分组，
> 用字符串比较来排序。也就是说必须写满 `年-月-日` 且月、日都是两位数。
> 写成 `2026-7-1` 或者 `2026/07/10`，分组会错乱（不会报错，但会分到奇怪的地方去）。
> 在网页里用【＋ 新增】不会有这个问题，日期默认就是标准格式。

> 建议日常都在网页里编辑。手改 JSON 容易漏逗号、漏引号，而且正文换行要写成 `\n`，很麻烦。

## 八、代码导读（按这个顺序读）

`app.js` 里的函数，按理解顺序排：

| 顺序 | 函数 | 干什么 |
| --- | --- | --- |
| 1 | `start()` | 入口：先看缓存，没有就读文件；读完画分类和列表 |
| 2 | `showList()` | 左边列表的总入口，四步：**筛选 → 分组 → 拼 HTML → 塞进页面** |
| 3 | `filterNotes()` | 按关键词 + 分类筛出要显示的记录（返回新数组，不改原数据） |
| 4 | `showNote(id)` | 右边显示：顶部按钮 + 标题 + `marked.parse()` 渲染正文 |
| 5 | `addNote()` | 4 个 `prompt()` → `notes.push()` → 存缓存 → 刷新 → 打开新那条 |
| 6 | `editNote()` | 2 个 `prompt()` → 直接改数组里那个对象的字段 |
| 7 | `deleteNote()` | `confirm()` → `notes.splice(下标, 1)` → 自动打开第一条 |
| 8 | `searchNotes()` / `selectCat()` | 搜索框和分类药丸的事件处理 |
| 9 | `toggleMonth()` | 折叠/展开某个月份 |
| 10 | `saveToFile()` / `downloadData()` | 两种保存方式 |
| 11 | `showCats()` / `collectCats()` | 从数据里收集分类，画成顶部那排药丸 |
| 12 | 小工具 | `sortNotes` / `findIndexById` / `isCurrent` / `getMonthKey` / `getMonthName` / `getDayText` / `escapeHtml` / `highlight` / `today` / `saveCache` |

几个关键设计，注释里都写了原因：

- **列表用 `id` 定位，不用数组下标。** 因为列表会被分组、被筛选，下标随时在变；
  `onclick="showNote(13)"` 里的 `13` 是那条记录的 `id`，永远找得到。
  （这是从上一版改过来的，上一版用下标，一加筛选就会点错。）
- **`escapeHtml()`**：把标题里的 `<` `>` `&` 换成实体，否则一个尖括号就能把页面结构弄乱；
- **`highlight()`**：先把文字转义、再找关键词，顺序不能反；
- **分类药丸传的是"第几颗"（数字下标）**，不是分类名字字符串——
  名字里万一有英文单引号会把 `onclick="..."` 的引号弄乱，传数字绝对安全；
- **点"取消"时 `prompt()` 返回 `null`**，所以每个输入都要判断 `== null`；
- **折叠状态 `collapsed` 不进 localStorage**：它只是"看的时候怎么摆"，不是数据。

`app.js` 最末尾还有一段"调试小技巧"注释：按 F12 后可以用 `notes`、`notes.length`、
`keyword`、`filterNotes().length`、`localStorage.getItem('notes')` 这些命令直接查看状态。

> ⚠️ **不要改 `tools/server.ps1` 的保存编码**：它里面有中文注释，
> 必须存成 **UTF-8 带 BOM**。Windows PowerShell 5.1 读没有 BOM 的 `.ps1` 会按系统默认编码
> （中文系统是 GBK）去解码，中文会乱码，严重时直接报语法错误。
> 用 VSCode 改的话，右下角编码要选 `UTF-8 with BOM`。

## 九、常见问题

**Q：右上角点【＋ 新增】没反应？**
A：是不是在无痕窗口里？`prompt()` 在无痕模式下可能被拦。正常窗口不会有问题。

**Q：搜不到明明有的内容？**
A：两个常见原因：① 关键词是按"包含"匹配的，别搜一整句话，搜一两个词；
② 分类筛选还开着，先把分类切回【全部】。

**Q：点了【💾 保存到文件】说连不上？**
A：三种可能：① 是直接双击 `index.html` 打开的（改用 `启动知识库.bat`）；
② 是在 GitHub Pages 线上版本（本来就没有后端，改用【⬇ 下载数据】）；
③ 服务器窗口被关掉了。不用慌，失败时它会自动帮你下载 `notes.json`。

**Q：能自动保存到 `data/notes.json` 吗？**
A：能，点【💾 保存到文件】。**但浏览器不会在你自己打字的时候自动写文件**——
网页里的 JS 没有权限直接动你的硬盘，必须通过本地服务器中转（`POST /api/save`）。
这是浏览器的安全设计，不是代码偷懒。

**Q：代码块没有颜色？**
A：为了遵守"只允许 marked.js 一个第三方库"，没引代码高亮库（highlight.js）。
代码块现在只有背景和边框。想要高亮就得再加一个库（本地放一份即可），
需要的话说一声——这会打破"只有一个第三方库"的约定，所以先不动。

**Q：能不能换配色？**
A：`index.html` 里 `<style>` 里：`background: #0d1117`（底色）、`color: #e6edf3`（文字色）、
`#58a6ff`（蓝色：分类标签、选中竖线）、`#1f6feb`（选中分类药丸的蓝底）。

**Q：手机上能看吗？**
A：窄屏（不超过 700px）时列表会自动跑到上面、内容在下面，顶部工具栏会换行排，
搜索框拉满整行，可以看也可以编辑。

**Q：改坏了想退回上一个版本？**
A：两种情况：
- **数据改坏了**：`data/notes.json.bak` 里是上一次保存前的版本，复制回来，再清一下浏览器缓存；
- **代码改坏了**：用 Git 退回，`git log` 看历史，`git checkout 某个提交号 -- 文件名` 单独恢复一个文件。

## 十、技术栈与约束

- **技术栈**：HTML5 + CSS3 + 原生 JavaScript ｜ 仅依赖 marked.js（本地文件，不联网也能用）
- **刻意不用的东西**：Vue / React / jQuery / 任何 CSS 框架 / 任何打包工具（webpack、vite）
- **刻意不写的语法**：箭头函数、模板字符串、解构赋值、`const`、`map / filter / forEach` / `async-await`
- **理由**：这个项目的代码要能被大一刚学完基础语法的我看懂并独立维护。
  代码短一点、笨一点没关系，**看得懂**最重要。
