## 1. 这是什么

三份**可交互的可视化思维导图**，把「JavaWeb 全链路 + 个人博客项目」拆成三个视角。
每份都是**单个自包含 HTML**：样式、脚本、数据全部内联，无任何外部依赖。

| 视图 | 文件 | 回答什么问题 | 规模 |
|---|---|---|---|

| **长链图** | `chain.html` | 数据**怎么一步步流动** | 6 阶段 / 44 环节 / 228 细节 |
| **博客源码** | `blog.html` | 这个项目的源码**怎么跑起来** | 259 节点 / 深度 3 / 14 个阶段 |
| **数据分析** | `llm.html` | NumPy/Pandas **学到哪了** | 129 节点 / 5 阶段（第 1~20 节） |

三份共用同一套**学习状态标记**机制，顶部有切换栏可互相跳转。

## 5. 三个视图分别在讲什么

### 5.1 思维导图（`index.html` · 353 节点）

以「用户注册」为案例，严格按数据流动时间顺序拆成六段：

```
阶段一 前端采集与发送 → 阶段二 网络传输 → 阶段三 后端接收解析
      → 阶段四 业务处理 → 阶段五 数据持久化 → 阶段六 响应返回
```

外加「阶段〇 全景速览」和附录 A~D（17 步时序图、常见错误对照表、面试追问、使用建议）。

覆盖知识点：HTML 表单、`v-model`、`@click`、axios POST、`async/await`、JSON、
HTTP 请求/响应报文、POST 与 GET、状态码、SpringBoot 启动类、内嵌 Tomcat、
SpringMVC 路由、`@RestController` / `@PostMapping` / `@RequestBody` / `@Autowired`、
三层架构、IoC/DI、MyBatis、`@Mapper`、动态代理、`#{}` 防注入、
HikariCP 连接池、DML、结果映射。

### 5.2 长链图（`chain.html` · 6 阶段 / 44 环节 / 228 细节）

6 个阶段横向串联成一条链，箭头标注每一环的**传递物**：

```
①前端 →JSON→ ②网络 →HTTP报文→ ③后端 →User对象→ ④业务
     →insert(user)→ ⑤持久化 →受影响行数→ ⑥响应 →回到前端
```

底部虚线回流箭头表示响应回到前端并渲染。
「阶段〇」和附录不参与主链，作为外挂内容保留在数据里（共 5 个）。

### 5.3 博客源码运行逻辑（`blog.html` · 259 节点 / 14 阶段）

```
阶段〇  全景速览                   阶段七  后端启动（Spring Boot）
阶段一  index.html 骨架            阶段八  NoteController 九个接口
阶段二  main.js 挂载（3 行有效代码） 阶段九  NoteService 业务层
阶段三  api.js 数据源判定（双模式）  阶段十  JdbcNoteDao 与 SQL
阶段四  app.js 应用骨架（340 行）    阶段十一 测试（109 个用例）
阶段五  data.js 纯函数加工（213 行） 阶段十二 构建与部署
阶段六  storage/dates/utils        阶段十三 代码级完整时序
```

### 6.3 学习状态标记

每个**叶子节点**右侧有个小圆按钮：

| 颜色 | 含义 | 圆内符号 |
|---|---|---|
| 灰色虚线 | 未标记（默认） | 无 |
| 🔴 红色 | **不会** | ✕ |
| 🟡 黄色 | **仅了解** | ~ |
| 🟢 绿色 | **理解** | ✓ |

点一下循环：`未标记 → 不会 → 仅了解 → 理解 → 未标记`。
节点边框与底色同步变色，顶部实时统计四种状态数量。

**推荐用法**：先把「不会」全标红，逐个攻破改成黄、再改绿，顶部计数就是进度条。

### 6.4 标记存在哪、会不会互通（**最容易搞混，务必看**）

标记存在**浏览器的 localStorage**，不是存在文件里。键名分两套：

| 视图 | localStorage 键 | 是否互通 |
|---|---|---|
| 思维导图 `index.html` | `mm-marks-v1` | ✅ 两者**共用同一份**标记 |
| 长链图 `chain.html` | `mm-marks-v1` | ✅ 同上 |
| 博客源码 `blog.html` | `mm-marks-blog-v1` | ⚠️ **独立**，不与前两者同步 |

含义：在思维导图里标「不会」，切到长链图还是红色；但切到博客源码看不到。
这是有意设计——前者是「知识点掌握度」，后者是「源码理解度」，两套各自独立。

**换电脑 / 换浏览器时标记不会跟着走**，必须用导出 / 导入。

### 6.5 「载入作者标记」按钮（仅 index / chain 有）

### 6.6 导出 / 导入

| 按钮 | 作用 |
|---|---|

| `导入标记` | 选一个 json 恢复（**同路径以导入为准，其余保留**） |

**json 格式**：

```json
{
  "app": "前后端数据沟通全链路-学习标记",
  "version": 1,
  "exportedAt": "2026-10-22T13:00:00.000Z",
```

## 7. 技术实现要点（后期维护看这里）

### 7.1 结构

- **单文件自包含**：CSS / JS / 数据全内联，无 CDN、无字体文件、无网络请求
- **纯 SVG 绘制**：节点是 `<rect>` + `<text>`，连线是三次贝塞尔 `<path>`
- **数据内联为 `const DATA = {...}`**：一棵树，节点形如 `{t: 文本, c: 子节点数组, color: 颜色}`

### 7.2 布局

| 视图 | 算法 |
|---|---|
| 思维导图 | **双向树**：根居中，阶段按奇偶交替分到左右两侧，各自纵向树形展开 |
| 长链图 | **横向链式**：6 个阶段固定列宽横排，环节在其下方纵向堆叠 |
| 博客源码 | 与思维导图同一套双向树算法 |

### 7.3 文字测量与换行

用 **Canvas `measureText`** 真实测量文字宽度（不是按字符数估算），
再按「**CJK 单字成词、英文按空格切词**」做折行，避免出现 `Cont/roller` 这种把英文单词从中间劈开的排版。

> 历史坑：早期用「字符数 × 常数」估算宽度，导致长英文串溢出卡片、或明明放得下却加了省略号。

### 7.4 视图保持（`renderKeepNode`）

展开 / 折叠后布局会变，如果直接 `render()` 会调用 `fit()` 重新适配，**缩放和平移被重置**。

修复方案（`index.html` 与 `blog.html` 已实现）：

```js
function renderKeepNode(n){
  const ax = state.tx + n._x * state.scale;   // 记录被点节点渲染前的屏幕位置
  const ay = state.ty + n._y * state.scale;
  render(true);                                // true = 沿用当前缩放/平移
  state.tx += ax - (state.tx + n._x * state.scale);   // 把它挪回原处
  state.ty += ay - (state.ty + n._y * state.scale);
  apply();
}
```

`chain.html` 用的是较简版 `render(true)`：缩放不重置，但被点的卡片可能有轻微漂移。

### 7.5 标记路径规则

节点路径在渲染时按树结构生成：`r` 为根，每下一层拼一个 `-序号`。
所以**同一份 `source.md` 生成的树，路径稳定可复现**——这是导出/导入能跨机器工作的前提。

## 8. 如何修改内容

### 8.1 改文字（推荐路径）

1. 编辑 `source.md`（Markdown 大纲：`#` 根、`##` 阶段、`###` 环节、`####` 细节）
2. 细节正文**直接写在标题下一行**，解析器会把它并入节点标题
3. 用生成脚本重新生成 HTML

> **关键**：`mmparse.py` 会把每个 `####` 标题下面的正文合并进节点标题。
> 如果只写标题不写正文，导图里就会出现一堆只写着「详细过程」「关键细节」的空壳节点。

### 8.2 生成脚本（在仓库 `tools/mindmap/`）

| 脚本 | 作用 |
|---|---|
| `mmparse.py` | Markdown → 树（含正文合并） |
| `build_mindmap2.py` | 树 → 双向思维导图 HTML |
| `build_chain.py` | 树 → 横向长链图 HTML |
| `build_all.py` | 一键生成全部产物 + 自检（自动比对 DATA 是否与解析树一致） |
| `export_all.py` | 树 → 给 XMind 导入的折叠版 Markdown |
| `export_marks.py` | 标记 JSON → 带「所属阶段/环节」的 txt 清单 |
| `render_png.py` | Edge 无头模式截 PNG |
| `publish_github.py` | 发布到站点目录并提交推送 |
| `push_api.py` | 走 GitHub API 建提交（`github.com:443` 不通时的备用通道） |

**典型流程**：

```bash
python build_all.py          # 生成 HTML 与 md
python build_all.py --check  # 只比对不写盘，做回归检查
```

### 8.3 `blog.html` 是例外（重要）

**`blog.html` 没有生成脚本**——它是单独产出后手工放进 `src/main/webapp/mindmap/` 的。

要改它，两种方式：

- **小改**：直接编辑 `blog.html` 里的 `const DATA = {...}`（保持 JSON 结构）
- **大改**：照 `build_mindmap2.py` 的结构给它补一个生成器

改完记得同步三处：仓库、U 盘 `D:\mindmap\`、桌面副本（如有）。

### 8.4 发布

```bash
git add src/main/webapp/mindmap/
git commit -m "feat(mindmap): ..."
git push origin main        # 自动触发 Pages 部署
```

## 9. 常见问题排查（FAQ）

**Q1：双击打开是空白页**
浏览器版本过旧（需要支持 ES6 + SVG）。换 Edge / Chrome 新版本。
若用 IE 或某些老内核浏览器支持不佳，属正常。

**Q2：点切换栏跳转失败 / 404**
三个 HTML 不在同一目录。把 `index.html`、`chain.html`、`blog.html` 放回同一个文件夹。

**Q3：标记全没了**
- 清了浏览器缓存 / 用了无痕模式 / 换了浏览器 → localStorage 被清空
- 用「导入标记」选之前导出的 json 恢复
- 或点「载入作者标记」恢复 228 条初始快照（仅 index / chain）

**Q4：线上的还是旧版**
1. 先确认 `git push` 成功（`git status` 应显示 `up to date`）
2. 等 30–90 秒让 Actions 跑完
3. `Ctrl + F5` 强制刷新（CDN 有缓存）

**Q5：放大后点击节点，视图跳回去了**
已修复（2026-10-22，commit `c1894ba`）。
若仍复现，说明打开的是旧文件——把最新的 `blog.html` 覆盖过去。

**Q6：卡片文字溢出 / 英文单词被劈开**
已修复（改用 Canvas `measureText` + 按词折行）。
若再现，检查是否混入了旧版 HTML。

**Q7：中文变乱码**
三个 HTML 都是 UTF-8 编码。用编辑器另存时**不要**存成 GBK / ANSI。

**Q8：往 U 盘写文件报 `EISDIR` 或写入失败**
U 盘是 **FAT32**，不支持硬链接。用「另存为」或直接复制粘贴，不要用依赖硬链接的工具。

## 10. 已知限制

1. **标记不跨设备**：只存在当前浏览器 localStorage，必须靠导出/导入迁移。
2. **blog.html 标记独立**：与另两个视图不互通（键名不同）。
3. **chain.html 无 `renderKeepNode`**：点击阶段卡时被点卡片可能有轻微漂移（缩放本身不重置）。
4. **没有生成脚本覆盖 blog.html**：改它需手工编辑 DATA 或自建生成器。
5. **节点数量上限**：当前 353 节点渲染流畅；如果扩到 1000+ 需要做虚拟化/按需渲染。
6. **打印不友好**：面向屏幕交互设计，若要打印请用 `preview.png` 海报。
7. **PR 期不可交互的部分**：`preview.png` / `chain-preview.png` 只是静态图。

## 12. 交接清单（接手必读）

接手这个项目，你需要知道的最小信息：

1. **三个 HTML 都是自包含单文件**，改内容改 `source.md` 再跑 `build_all.py`
2. **三个 HTML 必须同目录**，切换栏才能用
3. **标记在浏览器里**，两套键：`mm-marks-v1`（导图+长链）、`mm-marks-blog-v1`（博客源码）
4. **改完要 `git push` 才会更新线上**，30–90 秒部署，`Ctrl+F5` 看结果
5. **`blog.html` 没有生成脚本**，是例外，改它要手工动 DATA
6. **U 盘是 FAT32**，写文件避开依赖硬链接的工具
7. 三个线上地址见第 2 节
